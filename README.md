# 별 헤는 밤 — 윤동주 교육용 앱

윤동주의 시를 **매일 한 편씩** 읽고, **미션**을 수행하고, **방(단톡방)에서 감상을 나누며**,
**도전과제와 랭킹**으로 이어 가게 만드는 교육용 웹앱(PWA)입니다.

- 정해진 시각에 **웹푸시 알림**으로 오늘의 시와 미션이 도착합니다.
- 감상 미션을 제출하면 **방에 자동으로 공유**되고, 다른 사람이 **응원(리액션)** 을 보낼 수 있습니다.
- 도전과제를 달성하면 봇(**동주 알림이**)이 방에 **축하 메시지**를 남기고 푸시 알림이 갑니다.
- 점수는 **주간 / 월간 / 전체** 기준으로 집계되어 방별·전체 랭킹에 반영됩니다.

주 사용 대상은 **성인 학습자·일반 독자**로 잡았습니다. 미션 문구와 봇의 말투는
과장된 칭찬 대신 담백한 인정 쪽으로 맞췄습니다.

## 빠르게 실행하기

```bash
npm install
cp .env.example .env          # 값은 그대로 두어도 동작합니다
npm start                     # http://localhost:3000
```

Node.js **22.5 이상**이 필요합니다. 데이터베이스는 Node에 내장된 `node:sqlite` 를 쓰므로
네이티브 빌드 의존성이 없습니다. 런타임 의존성은 `express` 와 `web-push` 둘뿐이고,
프런트엔드는 빌드 단계 없이 그대로 제공됩니다.

### 알림(웹푸시) 켜기

```bash
npm run keys                  # VAPID 키 한 쌍을 만들어 줍니다
# 출력된 두 줄을 .env 에 붙여 넣고 서버를 다시 시작하세요
```

키가 없어도 앱의 나머지 기능은 모두 동작합니다. 알림 화면에 "키가 없다"는 안내만 뜹니다.

> iOS/iPadOS 는 **홈 화면에 추가한 뒤**에만 웹푸시를 받을 수 있습니다(Safari 16.4+).
> 안드로이드 Chrome·데스크톱 브라우저는 그냥 됩니다.
> 웹푸시는 **HTTPS** 에서만 동작합니다(`localhost` 는 예외).

### 시연용 데이터

```bash
npm run seed                  # 방 하나 + 네 사람 + 지난 며칠치 활동
```

만들어진 아이디로 로그인하면(PIN 은 모두 `1234`) 랭킹·도전과제·채팅이 채워진 상태를 볼 수 있습니다.

### 테스트

```bash
npm test                      # node:test, 46개
```

## 미션은 이렇게 만들어집니다

매일 **한 편의 시**가 정해지고(날짜만으로 결정되므로 모두가 같은 시를 받습니다),
그 시에서 **세 가지 미션**이 만들어집니다. 난이도가 한쪽으로 쏠리지 않도록
아래 세 묶음에서 하나씩 뽑습니다.

| 묶음 | 갈래 | 예 |
|---|---|---|
| 가볍게 | `check` | 소리 내어 읽기, 한 연씩 천천히, 한 구절 외우기 |
| 자동 채점 | `quiz` | 다음 행 찾기, 끼어든 시어 찾기, 시인을 알아 가기, 언제 쓰인 시일까 |
| 글쓰기 | `text` | 필사하기, 한 줄 감상, 내 하루와 잇기, 시인에게 묻기, 한 구절 빌려 쓰기, 두 시 나란히 읽기 |

- `check` 는 스스로 체크합니다(낭독은 채점할 수 없으니까요).
- `quiz` 는 자동 채점됩니다. **틀리면 점수는 없지만 다시 풀 수 있습니다.**
- `text` 는 최소 글자 수만 봅니다. 일부 미션은 제출과 동시에 **방에 공유**됩니다.

같은 날짜·같은 시라면 미션은 언제 만들어도 동일합니다(시드 기반 결정적 생성).
시는 전체를 한 바퀴 돌기 전에 되풀이되지 않고, 이틀 연속 같은 시가 나오지도 않습니다.

## 도전과제

여섯 묶음, 23가지입니다 — **꾸준함 · 읽기 · 쓰기 · 알기 · 함께 · 점수**.
예: `첫걸음`, `세 밤의 별`(3일 연속), `일곱 밤의 별`, `스물여덟 밤`,
`별 헤는 사람`(시 10편), `하늘과 바람과 별과 시`(전 작품), `필사의 사람`,
`시어 사냥꾼`, `동무`, `응원단`, `부끄럼 없이`(1,000점).

달성하면 보상 점수가 들어가고, 방에 축하 메시지가 올라가고, 푸시 알림이 갑니다.
한 번 받은 과제는 다시 달성되지 않습니다.

## 알림이 나가는 시각

| 시각(기본값) | 하는 일 |
|---|---|
| 06:00 | 오늘의 미션 발행 + 각 방에 오늘의 시 안내 + 전체 푸시 |
| 08:00, 21:00 | 아직 미션이 남은 사람에게만 다시 알림 |
| 월요일 00:00 | 지난주 랭킹 마감 안내 |
| 03:00 | 만료된 세션 정리 |

`.env` 의 `MISSION_PUBLISH_HOUR`, `POEM_PUSH_HOURS`, `APP_TIMEZONE` 으로 바꿀 수 있습니다.
같은 알림이 두 번 가지 않도록 발송 기록(`push_log`)으로 한 번 더 거르므로,
서버를 다시 시작해도 중복 발송이 없습니다.

사용자는 **나 → 알림**에서 갈래별로 끄고 켤 수 있고, **방해 금지 시간**(예: 22시~7시)을
정할 수 있습니다. 자정을 넘는 구간도 제대로 처리됩니다.

## 구조

```
src/
  config.js            .env 읽기 + 기본값
  db.js                SQLite 스키마와 마이그레이션
  app.js  server.js    express 앱 / 진입점
  content/             데이터와 문구 (코드가 아니라 내용)
    poems.js             윤동주 작품 19편 + 해설
    quiz-bank.js         생애·배경 문제 15개
    missions.js          미션 템플릿 + 오늘의 시 선정
    challenges.js        도전과제 23개
    messages.js          봇이 하는 말
  services/            도메인 로직
    users.js  rooms.js  chat.js  missions.js
    challenges.js  stats.js  points.js
    activity.js          제출 → 공유 → 과제 → 알림을 잇는 곳
    push.js  scheduler.js
  routes/              HTTP 경계
  lib/                 rng · date · korean(조사) · bus(SSE)
public/                빌드 없는 프런트엔드 (index.html / app.js / styles.css / sw.js)
test/                  node:test
```

몇 가지 설계 결정:

- **점수는 원장(ledger)에 쌓습니다.** 합계를 따로 들고 있지 않고 항상 원장에서 더합니다.
  `(user, reason, ref)` 에 유일 인덱스를 두어 같은 일로 점수가 두 번 들어가지 않습니다.
- **채팅은 SSE** 로 흘려보냅니다. 서버 한 대 기준이며, 여러 대로 늘릴 때는
  `src/lib/bus.js` 를 Redis pub/sub 같은 것으로 바꾸면 됩니다.
- **퀴즈 정답은 서버에만 있습니다.** 클라이언트로 내보낼 때 `answer`·`explain` 을 지우고,
  문제를 푼 뒤에야 열어 줍니다.
- **조사 처리기**(`src/lib/korean.js`)로 "「십자가」를 / 「무서운 시간」을" 이 바르게 나옵니다.
  받침 유무를 보고 을/를, 은/는, 이/가, 과/와, 으로/로 를 고릅니다.

## API

| 경로 | 설명 |
|---|---|
| `POST /api/auth/signup` · `login` · `logout`, `GET /api/auth/me` | 계정 |
| `GET /api/missions/today` | 오늘의 시 + 미션 + 내 진행 상황 |
| `POST /api/missions/:id/submit` | 미션 제출 (`{text}` 또는 `{answer}`) |
| `GET /api/poems`, `/api/poems/:id`, `POST /api/poems/:id/read` | 시집 |
| `POST /api/rooms`, `/api/rooms/join`, `GET /api/rooms` | 방 |
| `GET/POST /api/rooms/:id/messages`, `POST .../:mid/cheer` | 채팅 · 응원 |
| `GET /api/rooms/:id/stream` | 새 메시지 실시간 수신 (SSE) |
| `GET /api/rooms/:id/ranking`, `GET /api/ranking` | 랭킹 (`?period=week\|month\|all`) |
| `GET /api/me`, `/api/me/challenges` | 내 기록 · 도전과제 |
| `GET/PUT /api/me/push*` | 알림 구독과 설정 |

## 저작권과 본문 교정

윤동주(1917~1945)의 작품은 한국 저작권법상 보호기간(사후 70년)이 **2015년에 만료**되어
공유(public domain) 저작물입니다. 자유롭게 쓸 수 있습니다.

다만 **이 저장소에 실린 본문은 널리 통용되는 표기를 따른 것이고, 정본과 대조한 것이 아닙니다.**
교육 현장에 배포하기 전에 아래와 대조해 교정하시기를 권합니다.

- 정음사, 『하늘과 바람과 별과 詩』(1955 증보판)
- 왕신영 외 엮음, 『사진판 윤동주 자필 시고전집』(민음사)

교정을 마친 작품은 `src/content/poems.js` 에서 `verified: true` 로 표시해 두면
어디까지 확인했는지 관리하기 좋습니다. 해설(`note`)과 퀴즈 해설은 이 저장소에서 새로 쓴 글입니다.

## 운영 시 확인할 것

- `.env` 의 `SESSION_SECRET` 을 반드시 임의의 긴 문자열로 바꾸세요.
  지정하지 않으면 서버가 켜질 때마다 새로 만들어 모든 로그인이 풀립니다.
- HTTPS 뒤에 두세요. 웹푸시가 요구하고, 세션 쿠키도 `NODE_ENV=production` 일 때
  `secure` 로 나갑니다.
- 리버스 프록시를 쓴다면 SSE(`/api/rooms/:id/stream`) 응답을 버퍼링하지 않도록 하세요.
  (nginx: `proxy_buffering off;` — 서버는 `X-Accel-Buffering: no` 를 이미 보냅니다.)
- `data/app.db` 가 실제 데이터입니다. 백업 대상입니다.
