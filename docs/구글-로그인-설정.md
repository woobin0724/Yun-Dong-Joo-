# 구글 로그인 설정하기

코드는 이미 다 들어가 있습니다. **자격증명만 넣으면 켜집니다.**
키가 없으면 로그인 화면에 구글 버튼이 아예 뜨지 않고, 아이디+PIN 로그인만 동작합니다.

> ⚠️ 아래 화면 이름과 메뉴 위치는 Google Cloud Console 개편에 따라 달라질 수 있습니다.
> 실제 화면과 다르면 **화면을 따라가 주세요.** 막히시면 어디서 막혔는지 알려 주시면 그 지점만 같이 풀겠습니다.

---

## 1. Google Cloud Console에서 자격증명 만들기

1. https://console.cloud.google.com 접속 → 프로젝트 만들기
2. **API 및 서비스 → OAuth 동의 화면**
   - 사용자 유형: 외부(External)
   - 앱 이름: `별 헤는 밤` / 지원 이메일: 본인 이메일
   - **범위(scope)는 추가하지 마세요.** 이 앱은 `openid`, `email`, `profile` 만 쓰는데
     이 셋은 기본이라 따로 등록할 필요가 없습니다.
   - 테스트 중에는 "테스트 사용자"에 쓸 계정을 등록해 두면 됩니다.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 리디렉션 URI** 에 아래를 등록
     ```
     http://localhost:3000/api/auth/google/callback
     ```
     배포 주소가 정해지면 그것도 추가합니다 (Phase 6):
     ```
     https://<배포주소>/api/auth/google/callback
     ```
4. 만들어진 **클라이언트 ID** 와 **클라이언트 보안 비밀** 을 복사합니다.

---

## 2. 값 넣기

### 로컬

`.env` 에 넣습니다. **이 파일은 저장소에 올라가지 않습니다**(`.gitignore`).

```bash
GOOGLE_CLIENT_ID=붙여넣기.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=붙여넣기
GOOGLE_REDIRECT_URI=http://localhost:3000/api/auth/google/callback
```

서버를 다시 시작하면 로그인 화면에 구글 버튼이 나타납니다.

### 배포 (Phase 6)

같은 값을 Render의 **Environment** 에 넣습니다. `GOOGLE_REDIRECT_URI` 만 배포 주소로 바꿉니다.
**클라이언트 보안 비밀은 절대 코드나 저장소에 넣지 마세요.**

---

## 3. 자격증명 없이 흐름만 눌러 보기

실제 구글 키가 없어도 로그인 흐름 전체를 확인할 수 있습니다.
개발용 가짜 구글 서버가 들어 있습니다. **서명은 진짜 RSA 키로 하기 때문에**
검증 코드가 실제로 도는 것까지 확인됩니다.

```bash
# 터미널 1 — 가짜 구글
node scripts/fake-google-server.js

# 터미널 2 — 앱
GOOGLE_FAKE_BASE=http://127.0.0.1:4100 \
GOOGLE_CLIENT_ID=fake-client-id \
GOOGLE_CLIENT_SECRET=fake-secret \
GOOGLE_REDIRECT_URI=http://127.0.0.1:3100/api/auth/google/callback \
PORT=3100 npm start

# 터미널 3 — 브라우저로 자동 확인 (선택)
node scripts/verify-google-login.js screenshots/google http://127.0.0.1:3100
```

`GOOGLE_FAKE_BASE` 는 **`NODE_ENV=production` 에서는 무시됩니다.**
실수로 켜 둔 채 배포하면 아무나 로그인할 수 있게 되기 때문에, 코드에서 아예 읽지 않습니다.
(이 규칙은 테스트로도 고정해 두었습니다.)

## 이 앱이 하는 일과 하지 않는 일

**받는 것**
- 구글 계정 식별자(`sub`), 이메일 주소, 이름 — 요청 범위는 `openid email profile` 뿐입니다.

**하는 것**
- 이메일은 **계정을 알아보는 데에만** 씁니다. 화면·랭킹·채팅 어디에도 나오지 않습니다.
- `id_token` 은 구글의 공개키(JWKS)로 **서명까지 검증**합니다.
  발급자·대상(aud)·만료·이메일 확인 여부도 함께 봅니다.
- CSRF 는 `state`, 인가 코드 가로채기는 **PKCE(S256)** 로 막습니다.

**하지 않는 것**
- **이메일이 같다고 기존 계정에 자동으로 붙이지 않습니다.**
  남의 이메일을 선점해 계정을 가로채는 길이 되기 때문입니다.
  계정 연결은 로그인한 상태에서 본인이 직접 누를 때만 합니다.
- refresh token 을 받지 않습니다(`access_type=online`). 로그인 한 번이면 끝이라 필요가 없습니다.
- 구글 로고 이미지를 쓰지 않습니다. 구글 상표에는 별도 표기 지침이 있어서,
  버튼을 글자만으로 만들었습니다. 공식 버튼 에셋을 쓰시려면 구글의 브랜드 지침을 확인해 주세요.

---

## 확인이 필요한 법적 사항

미성년자의 개인정보 수집에는 보호자 동의 등 별도 요건이 적용될 수 있고,
구글 계정 자체에도 연령 정책이 있습니다.
학교·기관에 배포하실 계획이면 **해당 기관의 개인정보 담당자나 관련 지침을 확인**해 주세요.
이 문서는 법률 자문이 아닙니다.

아이디+PIN 가입을 계속 남겨 둔 이유도 여기에 있습니다 —
이메일을 주고 싶지 않거나 구글 계정이 없는 학생도 쓸 수 있어야 합니다.
