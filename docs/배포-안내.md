# 배포 안내 — 선생님과 반 친구들이 주소 하나로 쓰게 하기

이 문서는 「별 헤는 밤」을 인터넷에 올려서, 휴대폰으로 주소만 열면 누구나 쓸 수 있게 만드는 방법입니다.
코드를 몰라도 따라 할 수 있게 썼습니다. 처음이라면 **1장부터 차례대로** 하세요.

> **Streamlit 으로는 열 수 없습니다.** Streamlit 은 파이썬 프로그램을 띄우는 도구이고, 이 앱은 Node.js(Express) 서버입니다.

---

## 0. 먼저 알아 둘 것 — 기록이 사라지지 않게

학생들의 기록(걸어온 길, 필사, 점수, 방의 글)은 서버 안의 **파일 하나**(`app.db`)에 저장됩니다.
그래서 **서버를 다시 켜도 지워지지 않는 저장 공간(영구 디스크)** 이 꼭 있어야 합니다.

- 무료 호스팅 중에는 서버를 다시 켤 때마다 파일을 지우는 곳이 많습니다. 그런 곳에 올리면 **배포할 때마다 모든 학생의 기록이 사라집니다.**
- 아래 Render 설정은 영구 디스크를 붙이므로 **유료(Starter) 요금제**를 씁니다. 요금은 Render 화면에서 직접 확인하세요. 요금표는 자주 바뀌어서 이 문서에 적지 않았습니다.

## 2. 코드를 `main` 에 합치기

지금 새 기능은 `redesign/v2` 브랜치에만 있고 `main` 에는 없습니다. Render 는 보통 저장소의 기본 브랜치(`main`)를 올리므로 먼저 합칩니다.

1. GitHub 저장소 → **Pull requests** → **New pull request**
2. `base: main` ← `compare: redesign/v2` 를 고르고 **Create pull request**
3. 확인하고 **Merge pull request**

(Claude 에게 "PR 열어 줘"라고 하면 2번까지 대신 해 줍니다.)

## 3. Render 에 올리기

저장소에 들어 있는 `render.yaml` 이 서버 설정·디스크·비밀 키를 한 번에 만들어 줍니다.

1. <https://dashboard.render.com> 에 로그인합니다.
2. 오른쪽 위 **New** → **Blueprint** 를 누릅니다.
3. GitHub 연결을 허락하고 `Yun-Dong-Joo-` 저장소를 고릅니다.
4. Render 가 `render.yaml` 을 읽어 만들 것을 보여 줍니다. 아래 셋이 보이면 맞습니다.
   - 웹 서비스 `byeol-heneun-bam` (Starter)
   - 디스크 `byeol-data` (1GB, `/var/data`)
   - 환경 변수 `SESSION_SECRET` (자동 생성)
5. **Apply** 를 누르고, 결제 정보를 넣으라고 하면 넣습니다.
6. 배포 기록(Logs)이 흘러가다가 `Your service is live` 비슷한 문구가 나오면 끝입니다.
7. 화면 위쪽에 `https://byeol-heneun-bam-xxxx.onrender.com` 같은 **주소**가 생깁니다. 이 주소를 선생님께 드리면 됩니다.

### 지역(서버 위치)

`render.yaml` 의 `# region: singapore` 앞의 `#` 을 지우면 한국에서 가까운 싱가포르에 서버를 만듭니다. **서비스를 만든 뒤에는 바꿀 수 없으니** 3번 전에 정하세요. 이 값이 Render 에서 그대로 통하는지는 확인하지 못했습니다. 오류가 나면 `#` 을 다시 붙이세요.

## 4. 잘 올라갔는지 확인 (5분)

| 확인할 것 | 어떻게 | 기대하는 결과 |
|---|---|---|
| 서버가 살아 있다 | 주소 뒤에 `/api/health` 를 붙여 열기 | `{"ok":true,"timezone":"Asia/Seoul",…}` |
| 가입이 된다 | 휴대폰으로 주소를 열고 가입 | 하루 목표를 묻는 화면 |
| 레슨이 된다 | '길에 들어서기' → 마디 하나 끝내기 | 점수가 오름 |
| **기록이 남는다** | Render 에서 **Manual Deploy → Deploy latest commit** 으로 한 번 다시 배포한 뒤 다시 열기 | 로그인이 그대로이고 걸은 마디가 남아 있음 |

마지막 줄이 가장 중요합니다. 다시 배포한 뒤 기록이 사라졌다면 디스크가 붙지 않은 것입니다. 8장을 보세요.

### 휴대폰에서 앱처럼 쓰기

주소를 연 뒤 브라우저 메뉴에서 **홈 화면에 추가**를 누르면 앱 아이콘이 생깁니다.

## 5. (선택) 알림 켜기

알림 키가 없어도 앱은 그대로 돌아갑니다. 「나」의 알림 칸에 "지금은 켤 수 없습니다"가 뜰 뿐입니다.

1. 내 컴퓨터에서 저장소 폴더를 열고 `npm run keys` 를 실행합니다.
2. 나온 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` 를 Render 서비스 → **Environment** 에 넣습니다.
3. `VAPID_SUBJECT` 에는 `mailto:선생님이메일@학교.kr` 처럼 연락받을 주소를 넣습니다.
4. **Save Changes** 를 누르면 다시 배포됩니다.

## 6. (선택) 구글 로그인 켜기

`docs/구글-로그인-설정.md` 를 따르세요. 리디렉션 주소에는 배포 주소를 넣습니다.

```
https://<배포 주소>/api/auth/google/callback
```

그리고 Render **Environment** 에 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` 를 넣습니다. 비워 두면 아이디 + PIN 로그인만 됩니다.

## 7. 백업 — 학기 중에 한 번씩

Render 서비스 → **Shell** 에서:

```bash
npm run backup
```

`/var/data/backups/app-날짜시각.db` 가 생기고, 사용자 수와 무결성 검사 결과가 나옵니다. 서버가 켜진 채로 해도 됩니다.

- 이 백업은 **같은 디스크**에 생깁니다. 실수로 지운 경우나 업데이트가 데이터를 망친 경우는 막지만, 디스크 자체가 사라지면 함께 사라집니다.
- Render 디스크에 스냅샷(자동 백업) 기능이 있는지는 대시보드의 **Disks** 항목에서 확인하세요. 이 문서를 쓸 때는 Render 문서 사이트를 열 수 없어 확인하지 못했습니다.

### 되돌리기

되돌리면 백업 이후에 생긴 기록은 사라집니다. 정말 필요할 때만 하세요.

```bash
ls /var/data/backups                                    # 되돌릴 파일 고르기
cp /var/data/backups/app-20261012T0530.db /var/data/app.db
rm -f /var/data/app.db-wal /var/data/app.db-shm
```

그다음 바로 **Manual Deploy → Restart service** 를 누릅니다.

## 8. 문제가 생기면

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 배포 로그에 `SESSION_SECRET 이 없거나 너무 짧습니다` 가 나오고 꺼짐 | 세션 키가 없거나 24자보다 짧음 | **Environment** 에 `SESSION_SECRET` 을 긴 무작위 문자열로 넣기. 만드는 법: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` |
| `No such built-in module: node:sqlite` | Node 가 22.13 보다 낮음 | **Environment** 의 `NODE_VERSION` 을 `~22.22.0` 로 |
| 배포할 때마다 모두 로그아웃됨 | `SESSION_SECRET` 이 배포마다 바뀜 | 한 번 정한 값을 그대로 두기 |
| **배포할 때마다 기록이 사라짐** | 디스크가 없거나, `DB_PATH` 가 디스크 밖 | 서비스에 디스크가 붙어 있는지, `DB_PATH` 가 `/var/data/app.db` 처럼 **디스크 경로 안**인지 확인. 로그에 `DB_PATH 가 상대 경로` 경고가 있으면 이것 |
| 로그인했는데 새로 고치면 풀림 | https 가 아닌 주소로 접속 | Render 주소(`https://…`)로 열기. 9장의 학교 서버라면 그쪽 설명 참고 |
| 첫 화면이 오래 걸림 | 서버가 막 켜지는 중 | 잠시 기다리면 "서버에 닿지 못했습니다 · 다시 시도"가 나오고, 다시 누르면 들어갑니다 |

## 9. Render 말고 다른 곳에 올리기 (Railway · Fly.io · 학교 서버)

저장소의 `Dockerfile` 을 쓰면 Docker 를 돌리는 곳 어디서나 같은 모습으로 뜹니다.

```bash
docker build -t byeol-heneun-bam .
docker volume create byeol-data
docker run -d --name byeol -p 80:3000 \
  -e SESSION_SECRET="$(node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))")" \
  -v byeol-data:/data \
  byeol-heneun-bam
```

- 학생 기록은 `/data/app.db` 에 쌓입니다. **`-v ...:/data` 를 빼면 컨테이너를 다시 만들 때 모두 사라집니다.**
- `SESSION_SECRET` 은 한 번 만든 값을 적어 두고 계속 같은 값을 쓰세요.
- 백업: `docker exec byeol npm run backup`
- **https 없이** 학교 내부망 주소(`http://…`)로만 띄울 수밖에 없다면 `-e COOKIE_SECURE=false` 를 더하세요. 그러지 않으면 로그인이 유지되지 않습니다. 다만 같은 망의 다른 사람이 로그인 쿠키를 엿볼 수 있으니 **시연·임시용으로만** 쓰세요.

이 이미지는 이 작업 환경에서 실제로 빌드해 아래를 확인했습니다.
- 세션 키 없이 띄우면 시작하지 않는다.
- 세션 키를 넣으면 헬스체크가 `healthy` 가 된다.
- 쿠키에 `Secure; HttpOnly; SameSite=Lax` 가 붙는다.
- 컨테이너를 지우고 새로 띄워도 로그인과 필사가 그대로 남는다.
- 켜진 채로 `npm run backup` 이 된다.
